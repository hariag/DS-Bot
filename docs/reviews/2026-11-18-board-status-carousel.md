# 看板状态视图：3D 焦点切换

- 日期：2026-11-18
- 基准：`main` @ `3da3756a`（7 列状态视图合并后）
- 问题：按状态分列后仍有 7 个工作流列，横向铺满一页，定位目标需要反复左右滚动；希望默认只展开中间一张状态卡，左右两侧露出相邻状态卡的一部分，并保留点击切换。

## 1. 交互模型

```
[状态 chip：起草中 0 | 待准备 6 | 等待中 0 | 进行中 1 | 待验收 1 | 完成 0 | 已取消 0]
[3D 焦点区：左侧相邻卡（局部） | 当前状态卡（放大、高亮） | 右侧相邻卡（局部）]
[当前状态的卡片区：响应式网格，保留列菜单/加卡/空状态]
```

- **状态 chip**：所有状态始终可点，显示数量；点击直接跳转，不需要逐张翻。支持 `ArrowLeft` / `ArrowRight` / `Home` / `End`。窄屏时 chip 条横向滚动，当前状态自动滚入可视区。
- **3D 焦点卡**：当前状态居中放大，左右相邻状态缩小、旋转、降低不透明度并露出局部；点击左右卡即可把该状态展开为新的中心卡。更远的状态用上方 chip 直接跳。
- **当前状态卡片区**：只渲染当前状态的卡片，桌面端 3 列自适应网格，窄屏单列；保留原有列菜单（重命名、左右移动、归档全部）、加卡、空状态和快捷添加。
- **拖动**：
  - 同一列内拖动卡片仍可排序；
  - 把卡片拖到上方某个**状态 chip / 状态卡**上，按原状态机执行 submit（起草→待准备）、schedule（待准备/等待→进行中）、restore（已取消→待准备）或 cancel（任意→已取消）；
  - 3D 相邻卡只是预览，不作为放置目标，避免在缩略卡上做精确拖放。
- **默认焦点**：优先「进行中」有卡片时聚焦进行中；否则聚焦第一个有卡片的状态；都为空时聚焦「待准备」。这样打开看板先落在有工作的地方。
- 旧群目标卡仍在上方的「目标卡片」独立区域，不参与工作流焦点切换。

## 2. 兼容与边界

- 任务账本、调度器、独立验收、Release 门禁、proposal 规则均未改动；`ready` 仍与「等待中」同列显示。
- 状态 chip 的顺序跟随现有列排序偏好；重命名/左右移动列后，chip 与焦点卡同步。
- 焦点状态只保存在当前看板会话内，刷新后按默认规则重新选择；不写 localStorage。
- 3D 焦点卡对辅助技术隐藏（`aria-hidden`），所有状态切换由可访问的 chip tablist 提供，避免重复朗读。
