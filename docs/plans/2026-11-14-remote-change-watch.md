# Remote change watch

An optional owner-configured watch uses the existing GitHub token only when the chosen Bot is allowed to use it. The Host keeps the credential in memory and never exposes it in its status or event records. It uses GitHub's HTTPS REST API, has no model turn, and sends no messages.

`remoteChangeWatch` accepts `repository` (`owner/name`), `branch`, `ownerBotId` and an optional `initialCursor` containing a previously observed 40-character commit SHA. It is off when omitted. The cursor is a starting point, not proof that earlier history was checked; the personal board says so. Only the owner board can see the status and the most recent change records.

The comparison is pinned to immutable base and head commits. A proven fast-forward is scanned in batches; progress and qualifying events are saved with the cursor in private SQLite storage under the team home lock. Only changes whose complete file list, including both sides of a rename, is entirely under `team/patrol/` are filtered. Empty or indeterminate file lists are recorded for review. The cursor advances only after all pages and file lists have been inspected, the observed branch still contains the pinned head, and the Host rechecks the PM's credential scope and lock. A crash or failed request retains the prior cursor and pending batch. The commit SHA is the event key, so retry does not create a second record.

The check runs every 15 minutes when healthy and uses short follow-ups to finish a backlog. More than 1,000 commits, a force push or incomplete GitHub pagination yields a visible reconciliation state rather than silently moving the cursor. GitHub's commit API caps the returned file list at 3,000, so an incomplete list also remains unprocessed. GitHub history can change immediately after the latest response: the displayed check time is the time the saved observation completed, not a continuous freshness guarantee. Automatic PM notification and proactive task dispatch are deliberately outside this watch; an owner can inspect the locally visible records.
