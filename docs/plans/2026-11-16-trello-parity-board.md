## 为什么

现有任务看板已经有稳定的任务账本、版本校验、操作回执、共享授权、图片校验和 Goal 卡片兼容，
但界面仍像一个“任务详情页”：卡片信息以标签和文字堆叠，详情、评论、图片分别藏在多个按钮后面；
创建、拖动、评论、上传的入口和反馈不统一；视觉上也没有沿用 DeepSeek Harness / DS Bot 的
13/18 正文、11/16 注释、12px 卡片、发丝边和安静悬停的界面语言。用户要求把看板补到 Trello
的卡片体验，并按 Harness 风格重做，且对新建、拖动、评论、图片上传做系统性验证。

## 已定的行为

### 看板与卡片

- 每个群、每个个人范围各有一块看板。群看板沿用任务工作流列表（准备中、等待、就绪、进行中、
  待验收、已完成）；个人看板另有“待办 / 进行中 / 个人已完成”进度列表。工作流状态仍由任务账本
  和 Bot 流程决定，列表不是可任意增删的自定义列表。
- 卡片正面显示：封面、标题、标签、截止日期（逾期/已完成状态）、检查项进度、描述标记、评论数、
  图片数、负责人。第一张图片在没有显式封面时作为封面；没有图片时不占封面高度。
- 封面可在卡片详情的附件里选择：“设为封面 / 移除封面”，封面引用保存在任务卡详情里；
  删除被引用的图片时封面自动清空。
- 卡片按创建时的稳定顺序排列；同列拖动可以调整顺序，跨列拖动只在工作流允许的动作内生效：
  可派发的卡片拖到等待/就绪/进行中会派发；个人卡片可在三个进度列之间拖动。其他跨列拖动
  给出明确提示，不伪造状态变化。
- 新建卡片使用一个统一对话框：标题、负责人、独立验收人、验收标准、依赖、可选描述。看板每个
  列表底部有安静的“添加卡片”入口；点击后先出现 Trello 式行内标题输入，回车后用该标题打开
  完整对话框。个人进度列创建的卡片默认标记为该列。
- 卡片详情使用两栏对话框：主栏是描述、检查项、图片、评论和活动；侧栏是状态、负责人/验收人、
  截止日期、标签、依赖、证据、共享和修订历史。所有编辑仍走原来的操作回执和版本 fence。
- 描述、截止日期（日期 + 可选时间 + 完成标记）、标签、检查项都可以在详情里直接编辑。
  标签使用稳定的颜色映射；检查项可以勾选、编辑文字和删除，立即保存，但不代表任务完成或依赖完成。
- 评论支持发表、编辑、删除；图片支持文件选择、拖入和粘贴，保留原有 20 张/任务、10 张/批、
  5 MiB/张、20 MiB/批和 PNG/JPEG 限制，并保留不可确定的写入结果待核对语义。
- 搜索覆盖标题、描述、标签、评论、负责人和 ID；提供负责人、标签、截止日期筛选。
- 保留恢复、共享授权、Goal 卡片、只读和能力限制；这些入口在新界面里仍然可见、可用。

### 视觉

- 全部颜色来自 `--bt-*` / `--dsw-alias-*` 主题变量；不写死品牌色。
- 字号只用 11/16、12/18、13/18、14/22、15/20、17/24、20/28；卡片标题 13/18/500，
  看板标题 17/24/500，卡片详情标题 17/24/500，分区标题 13/18/600。
- 圆角：卡片/列表 12，对话框 16，输入框 8，按钮/标签 999 或 4；发丝边 0.5px 用于浮起表面。
- 阴影只用 Harness 的高度档：卡片悬停轻阴影、菜单/弹层中阴影、对话框 0 24px 80px。
- 主按钮使用 Harness 的 `--dsw-alias-button-primary-fill`（浅色黑底白字、深色白底黑字），
  不再使用蓝色强调块；强调色只用于焦点环、选中和状态点。
- 动效只用于颜色/透明度（.12s）和表面变形（对话框使用 `SPRING_SHAPE`）；遵守
  `prefers-reduced-motion`；焦点环 2px accent，偏移 2px。
- 列表高度铺满可用区域，横向滚动隐藏滚动条但保留箭头导航；空列表是可放置的整块区域。
- 看板恢复/复核工具收起为一排紧凑的状态胶囊，展开后才占用空间。

## 不做什么

- 不做可自由增删的 Trello 列表，因为列表就是任务工作流状态；不接受用 UI 伪造状态。本机重命名/左右移动只影响显示。
- 不做永久删除卡片；任务账本保留审计。归档是可恢复的 `archivedAt`，不删除历史。
- 不做跨看板移动卡片、成员邀请、通知、Power-Up、模板等 Trello 外围功能；Release 变更通知项目群/PM 属于 DSBot 闭环，不在 Trello 外围功能内。
- 不改变操作回执、revision fence、依赖授权、共享授权和图片校验的安全语义。

## 已知限制

- 截止日期使用本地墙上时间（`YYYY-MM-DD` 或 `YYYY-MM-DDTHH:mm`），不保存时区；
  逾期判断以浏览器本地时间为准。
- 标签颜色由标签文本稳定散列得到，不保存单独的颜色配置。
- 工作流卡片跨列拖动只在“派发”动作上生效；开始、汇报、验收仍由 Bot 流程驱动。
- 封面只引用本卡附件；不支持外部图片 URL 或每张卡片单独上传封面文件。

## 验证

以下结果于 2026-11-16 在 Windows 工作站 `D:\DS-Bot` 的当前工作区实测；2026-11-17 收尾后重新跑了 browser fixture 和 board e2e。提交/推送状态以当前分支和 PR 为准，不在文档里写死。

- **真实 e2e**：`node test/e2e/board.e2e.mjs --fresh`，run `20261116115420`，mock bench + Chrome：
  **17 passed, 0 failed**。覆盖打开看板、快速新建、同列拖动排序、跨列派发、Bot 投递
  `accepted`、描述、标签、截止日期、检查项、评论发表/编辑/删除、PNG 上传与解码、封面设置、
  刷新持久化、控制台无错误。
- **浏览器 fixture**：`node test/task-board.browser.mjs`，同一工作区：
  **222 assertions, 0 failed**（约 17 秒）。覆盖恢复/复核面板、只读、容量、个人进度、
  快速新建（含个人看板独立验收人）、拖动派发、描述/标签/截止/检查项、评论、图片、封面、
  共享、取消、迟到响应、scope 隔离、移动端布局和焦点陷阱。
- **任务账本/API 单元测试**：`test/board-host/*.test.mjs` **61 pass**；其中封面字段、
  校验、删除清理和 board-list 投影均有新增用例。
- **相关宿主测试**：`groups`、`group-work`、`follow-through`、`board-host` 合并运行
  **405 passed, 1 failed, 2 skipped**；唯一失败是 Windows 测试环境无法创建指向
  `D:\etc\passwd` 的符号链接（`EPERM`），与看板代码无关。
- **完整 `npm test`**：2869 tests，2848 passed，9 failed。失败分布在 Windows 符号链接权限、
  缺少 `link` 构建依赖、Windows ACL、connectors/phone/local-agent 等本机环境用例；
  `roster` 和 `rounds` 的两个并发时序失败在单独运行时均通过（62/62、42/42）。
- **构建与 lint**：`node scripts/build-client.mjs --check` 通过；`npm run lint` 为
  96 warnings、0 errors（均为仓库既有 warning）。

e2e 产物在 `ds-bot/test/e2e/artifacts/`；运行方法见 `ds-bot/test/e2e/README.md`。
